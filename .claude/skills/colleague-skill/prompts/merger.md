# 增量 Merge Prompt

当用户追加新的原材料时，使用此流程将新信息整合到现有的 work.md 和 persona.md 中。

---

## 四步工作流

### Step 1：分类判断
将新内容按类型分配：
- → `work.md`：技术实现、业务流程、工作规范、专业观点
- → `persona.md`：沟通风格、行为模式、决策方式、人际关系
- → 两者都有：拆分后分别处理

### Step 2：冲突检测
比较新旧内容，识别关系类型：
- **补充**：新信息填补了空白，直接追加
- **确认**：新信息与现有结论一致，标注"已有 N 条证据确认"
- **矛盾**：新旧信息相互冲突，标注冲突并呈现给用户裁决

### Step 3：增量输出
```
原则：只追加，不覆盖

- 补充信息：直接追加到对应章节
- 确认信息：在现有条目后加 [+1确认]
- 矛盾信息：标注 [冲突：旧结论X vs 新证据Y，请用户裁决]
- 重复信息：忽略，不重复记录
```

### Step 4：更新摘要
```
本次更新摘要：

📝 work.md
  - 新增：{N} 条
  - 确认：{N} 条
  - 冲突待裁决：{N} 条

🧠 persona.md
  - 新增：{N} 条
  - 确认：{N} 条
  - 冲突待裁决：{N} 条

版本：v{X.Y} → v{X.Y+1}
```

---

## 关键原则

- **只追加不覆盖**：绝对避免意外删除已有知识
- **冲突不自动解决**：明确标记冲突，让人类决策
- **去重处理**：已确认的重复信息不再记录
- **版本号规则**：每次 merge 后小版本号 +1（如 v1.0 → v1.1）
