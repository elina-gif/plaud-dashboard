# Work Skill 生成模板

基于工作能力分析结果，生成标准化的 work.md 文件。

---

## 输出结构（8 个部分）

### 1. 职责范围
```
## 职责范围

### 负责系统/模块
{列出负责的系统、服务、模块}

### 业务域
{负责的业务领域}

### 文档维护
{维护的文档类型和位置}

### 职责边界
- 做：{明确负责的事项}
- 不做：{明确不负责的事项}
```

### 2. 技术规范（技术类职位）
```
## 技术规范

### 技术栈
{语言、框架、中间件、工具}

### 代码风格
{命名规范、注释习惯、函数长度等具体标准}

### 接口设计标准
{API 设计原则、错误处理、版本管理}

### Code Review 关注点
{审查时重点关注的方面，用具体标准而非形容词}
```

### 3. 工作流程
```
## 工作流程

### 需求处理
{从接到需求到开始执行的步骤}

### 方案编写
{技术方案/PRD/设计稿的写作习惯和结构}

### 问题处理
{发现问题到解决问题的标准流程}

### 交付流程
{代码提交、文档交付、汇报沟通的流程}
```

### 4. 输出风格
```
## 输出风格

### 文档风格
{详细程度、结构偏好、格式规范}

### 沟通方式
{偏好文字/图表/数据的情况，汇报粒度}

### 典型输出示例
{如有原材料中的真实例子，直接引用}
```

### 5. 经验知识库
```
## 经验知识库

### 踩坑记录
{具体的失败案例和教训，用引号标注原文}

### 技术观点
{明确的技术立场和观点}

### 最佳实践
{他/她总结的最佳实践，量化标准优先}
```

### 6. 使用说明
```
## 使用说明

激活此 Work Skill 后，以 {花名} 的专业标准处理以下类型任务：
- {适用场景 1}
- {适用场景 2}
- {适用场景 3}

不适用于：
- {超出其专业范围的场景}
```

---

## 生成原则

1. **信息完整性**：缺失维度标注 `（暂无足够信息，建议追加相关文档）`
2. **具体可执行**：避免模糊表述，使用量化标准
3. **格式规范**：使用清晰的 Markdown 层级结构
4. **证据导向**：关键结论附原文引用，用引号标注
